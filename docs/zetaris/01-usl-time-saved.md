# How the USL saved time compared with hand-coding

**Context.** Our due-diligence agent needs audited financials (revenue, net income, cash, operating cash flow, long-term debt) for a target company and a peer, tied to an industry classification. The data lives in three public REST APIs with three different JSON shapes: SEC EDGAR XBRL `companyconcept`, EDGAR `submissions`, and the company_dns SIC hierarchy.

## What we built in Zetaris

| Piece | Size | Wall-clock to build |
|---|---|---|
| 3 Lightning databases, 13 REST tables, 13 `CACHE TABLE` | generated by a 30-line loop in `zetaris_setup.py` | about 35 s to run, all 37 statements |
| USL `dd_usl`: 3 tables, 2 foreign keys, 2 primary keys | one `COMPILE USL` DDL block | under 1 s |
| Activation queries (UNION over 10 REST tables, `explode`, SIC map coercion) | 3 `ACTIVATE USL TABLE` statements | 3 s |
| Data-quality rule + the auto-generated PK/FK rules | 1 `REGISTER DQ` | under 1 s; `RUN DQ` checks 515 rows in about 6 s |

From the first `CREATE LIGHTNING DATABASE` to a working, DQ-checked semantic layer took about **40 minutes** of our time, most of it spent on three errors described in [03-usl-product-feedback.md](03-usl-product-feedback.md).

## What the same thing costs by hand

Our estimate of the hand-written equivalent in Python (we have written this kind of code before):

| Task | Hand-coded | With Zetaris |
|---|---|---|
| HTTP fetch with the SEC User-Agent, retry and rate limit for 13 endpoints | 1 h | `REST TABLE ... HEADER (user-agent ...)` |
| Parse three JSON shapes (array of facts, flat object, dynamic-key map) | 1.5 h | `LATERAL VIEW explode`, `from_json(to_json(...))` |
| Normalise restated values (each 10-K repeats prior years) | 1 h | one `ROW_NUMBER() OVER (...)` in SQL |
| Join company → industry, fact → company, check orphans | 1 h | foreign keys in the DDL; FK checks come free with `RUN DQ` |
| Data-quality checks and a report of failing rows | 1.5 h | `REGISTER DQ` + `SHOW DQ ALL INVALID TABLE` |
| Local caching so the agent does not hit SEC on every question | 1 h | `CACHE TABLE` |
| **Total** | **about 7 hours** | **about 40 minutes** |

## Where the time saving shows up after the build

- **The agent issues one SQL query, not 13 HTTP calls.** The Retriever's financial query runs against `dd_usl.financial_fact` in about 2.5 s (see the trace: `tool_call zetaris ... rows 30`). Adding a metric is one line in `METRICS`, not new parsing code.
- **Adding a company is one dictionary entry.** `COMPANIES` drives every REST table and both activation queries.
- **Quality is checked where the data lives.** The memo quotes "valid_reported_fact 515/515, cik 515/515", so the Critic can trust the financial evidence without re-checking it.
